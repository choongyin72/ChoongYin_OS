## Quirks
- **Original park reason ("pager-walk click timeout") was wrong, twice.** The real defect (found for
  issue #321, 2026-08-02): inserting with Business Unit left unset leaves `BUSINESS_UNIT_CODE` NULL,
  so the row is genuinely invisible under any page of a BU-scoped grid - the same class of bug as
  Message Group and Planned Well, not a pagination mechanism issue. Fixed by binding the navigator's
  captured Business Unit into the insert form's own Business Unit dropdown (`gen_ovgm.py`'s
  `parent_dd` mechanism).
- **`gen_ovgm.py`'s `nav_levels` config key only caps the Python driver's cascade - it does NOT
  affect the generated RF T3.** The RF T3 always emits `Apply OV-GM Navigator First Available`
  (tries nav columns 1-6), which times out on this screen's 2 unrelated optional filter columns
  (present but 0 options). Same class of gap as Service (CO.2103). Fix: hand-edit the generated T3
  to bypass the shared cascade keyword with a direct `Select First EC Dropdown Option` on the
  screen's own `${NAV_DD}` variable - purely local to the T3, no shared-file change.
- **Ambiguous class label**: "Price Object" matches both `PRICE_OBJECT` and `INVENTORY_PRICE_OBJECT`
  in `class_property_cnfg` (both share base tables `PRODUCT_PRICE`/`PRODUCT_PRICE_VERSION`). The
  correct view for THIS BF code is `OV_PRICE_OBJECT` (confirmed via the existing park doc's own
  earlier investigation, not re-derived this round).
