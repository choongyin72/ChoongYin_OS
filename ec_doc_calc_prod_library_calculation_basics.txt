 Library Calculation Basics 

 Introduction 

 Library calculations are a fundamental feature in Energy Components that enable modular, reusable calculation design. Understanding the distinction between Library Calculations (the actual calculation objects) and Calculation Libraries (the organizational containers) is essential for working effectively with this feature. This page covers the basic concepts, technical constraints, and benefits of library calculations. 

 Library Calculations vs Calculation Libraries 

 If you are familiar with EC&#8217;s calculation there is not a great deal extra to learn in terms of EC configuration. The Maintain Library Calculation screen is for the most part identical to the Maintain Calculation screen. This indicates that a Library Calculation is just like any other calculation object in EC and can consist of a list of equations, a (complex) process including sub-processes, or an Excel workbook calculation. The two key EC objects are described below. 

 Library Calculations 

 A Library Calculation is an independent calculation rule that can be plugged into, and reused, in other calculations. 

 It has an associated list set of variables and sets that must also be defined in the calling parent calculation. 

 They must be in scope when the library is called. 

 These act as pseudo signature , the input and output parameters and can be seen to represent the 'interface'. 

 Technically a library calculation will also be able to use all sets and variables from its calling process without those sets and variables being defined in the expected inherited sets and variables, however this is not to be done. 
 As part of best practices, always define all expected inherited sets and variables. 

 Calculation Context 

 Library Calculations are context specific, meaning a Library Calculation can only be used by other calculations within the same calculation context. 

 Recursion 

 EC&#8217;s implementation of library calculations does not support recursion . This means that a library calculation cannot call itself either directly or indirectly via a separate nested calculation. 

 The calculation engine checks for recursion at run-time, not design time. 

 This means you have to be careful when designing multiple layers of nested calculation libraries. 

 Calculation Libraries 

 Individual Library Calculations are organised into Calculation Libraries. The library in which a Library Calculation is defined has no impact on when and where that calculation can be used. The purpose of a library is only to apply logical grouping to different Library Calculations and make them easier to find and manage. 

 Ensure that custom libraries are properly prefixed with the extension prefix in use. 

 What is the Point of Calculation Libraries? 

 Product Standard EC library calculations 

 Product Standard library calculations (PSLC) are out of the box available calculations that are shipped with EC and maintained by the EC product. Specific guidelines on using product standard library calculations can be found here: Working with Product standard library calculations 

 Project specific library calculations 

 Project specific library calculations are created and maintained for specific EC systems or customers. They are not created or maintained as part of standard EC 

 Reuse 

 Copy blocks of equations from one place to another is not advisable. Reuse is about using the same logic to perform similar tasks as a way of increasing quality and reducing overhead. Logic within a specific calculation can often be applied in more than one situation,. either within the same calculation or within other calculations. Library calculations allow you to define separate components of calculation logic that can be reused more than once. This key concept in software design is known as planned reuse. 

 Standardization 

 The use of library calculations, especially those provided out of the box in EC product ensure a higher degree of standardization of the EC system. This will reduce upgrade and evergreening efforts for the asset. 

 Facilitation of Maintenance and Deployment 

 Large calculations can be broken into more manageable chunks on which individual developers can work in relative isolation from other ongoing changes. Promoting individual libraries through the DevOps pipeline is more manageable and carries less risk than an entire calculation rule.
