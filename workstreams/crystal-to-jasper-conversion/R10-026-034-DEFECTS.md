## Two corrections to R10-LAYOUT-AUDIT.md, both mine

**1. "Not one of these has a `detail` band, a `<query>`, or a `subDataset`" is WRONG.**
Six of the eight do have a `detail` band with `$F{}` fields. My check grepped `<detail ` with a
trailing space and silently missed every `<detail>` written without attributes:

| File | `<detail` | `$F{}` uses |
|---|---|---|
| R10.026 Average_ACQ_Balance | **2** | 10 |
| R10.029 AACQ_Notice_to_Buyer | 0 | 0 |
| R10.030 ADP_per_buyer / ADP_per_contract / SDS_per_buyer | **2** each | 13 each |
| R10.031 DES_Buyers_ADP / DES_Buyers_SDS | **2** each | 16 each |
| R10.034 Annual_Quantity_Statement | 0 | 0 |

So only **R10.029 and R10.034** are parameter-only with nothing repeating. The other six already
render N rows from a bound source — R10.031 ADP's cargo rows show real values (`IC25-CP-CP01`,
`Pacific Breeze`, `4,280,729`). Their page shortfall is not "the body was never built".

**2. R10.034's purple bands.** The audit reported 8 build bands against the original's 24 and
implied the fills are misplaced. The actual cause is simpler and provable: R10.034's JRXML
contains **no `#444080` at all** — it uses only `#0091B5` (teal). Every one of the original's
navy table-header bands is therefore absent, not merely offset.

## Verified across ALL EIGHT files

These are not per-report judgements; each was counted in the JRXML.

| # | Defect | Evidence |
|---|---|---|
| **A** | **No italic anywhere.** `isItalic="true"` occurrences = **0 in all 8 files.** | The originals use `Arial-BoldItalicMT` for the title, every info-block label, every section heading and every column header. This one defect accounts for more span mismatches than everything else combined. |
| **B** | **The purple rule under the logo is missing in all 8.** | No rectangle/line under 200pt, wider than 300pt, in any file. Every original has it (R10.034 at y≈300px/200dpi, R10.030 and R10.031 at y≈218px). |
| **C** | **No red anywhere.** Red colours used = **NONE in all 8.** | R10.034's original prints `(1,584,881)` and `(1,671,722)` in red; R10.029's prints `(3,831,047)` in red. The build prints all of them black. |
| **D** | **The teal accent is missing from 6 of 8.** | `#0091B5` is used only by R10.029 and R10.034. R10.026, R10.030 ×3 and R10.031 ×2 have **no teal**, yet each of their originals fills the info-block label column — and in R10.026 the `Contract Year` data cells — with it. |
| **E** | **Part F1 text drops — 22 elements silently render as nothing.** | `height="9"` on an 8.0pt style needs 9.6. R10.031 ADP **10**, R10.031 SDS **8**, R10.030 ADP_per_buyer **2**, R10.030 ADP_per_contract **2**. |

**Defect E is why two info blocks are simply not on the page**, which is the single most visible
difference in the zooms:

- **R10.031 DES_Buyers_ADP** — all 5 rows dropped (`Contract Year`, `Contract`, `Buyer`,
  `Date Of Issue`, `Version` and all five values). The build's page 1 has a ~500pt blank gap
  where the original's info table sits.
- **R10.031 DES_Buyers_SDS** — 4 rows dropped.
- **R10.030 ADP_per_buyer / ADP_per_contract** — the `Contract Year` row dropped, which is why
  the build shows only Buyer / Date Of Issue / Version against the original's five rows.
