## 2. The decision that shaped this report: TRACE, don't hand-build

R07.003–006 were hand-built and every one of them was dominated by the same defect classes —
columns invented rather than measured, cells that overlap or leave 1pt gaps (doubling every
border), values landing in the wrong box. Those cost roughly a dozen owner review rounds
between them.

R07.001 is instead **generated by tracing the reference PDF** (`build/gen_001.py`): every cell
rectangle, rule, and text span is emitted at the position Crystal itself uses, read out of the
reference's own `get_drawings()` and `get_text('dict')`.

That paid off immediately and measurably. The very first traced build had:
- font histogram **exact** on the first attempt (all four earlier reports needed font passes)
- 0 rule differences
- 1 value out of position, against R07.006's 47 and R07.003's 135

Architecture mirrors R07.003's verified shape: page 1 → `<title>`, pages 2–7 → one `<detail>`
band with 6 records gated on `$V{REPORT_COUNT}`. Band height 1107 (margins trimmed to fit the
reference's lowest content at local y 1092 + height 13).

## 3. Real defects found and fixed

### 3.1 Purple fills carried a 1pt grey pen — the "borderline thickness" defect, self-inflicted
The generator emitted every traced purple band as
`mode="Opaque" backcolor="#454087"` **with `<pen lineWidth="1.0" lineColor="#D6D6D6"/>`**.
A fill in Crystal is only a fill. That extra outline sat ~1pt from the traced border rectangle
on the same boundary, so two strokes rendered where the reference has one:

```
page 7, band y 122-158        gen      ref
  x=23  (table left frame)    1.98pt   1.02pt
  x=653 (column boundary)     1.98pt   1.38pt
  x=812 (table right frame)   1.02pt   1.02pt   <- unaffected, no fill edge there
```

Removing the pen (`lineWidth="0.0"`) took internal-consistency findings **14 → 0** across all
7 pages. This is the exact defect class the owner reported on R07.004, R07.005 and R07.006 —
here it had a single root cause and a one-line fix.

**Two wrong theories preceded this**, and both were only killed by measurement, not reasoning:
1. *cell-to-cell gaps between border rects* — built a full tiling pass, moved 313 rectangles,
   and the internal-consistency count did not change at all;
2. *frame-vs-cell doubling* — snapped the full-width frame rects too, and page 7 got slightly
   worse (812 started varying).

Only after listing the actual JRXML elements with an edge near abs x=23 (`build/`-adjacent
`diag_001_at.py`) did the `Opaque` rect with `pen=1.0` show up next to the `Transparent` one.
**Lesson repeated for the third time on this project: read the source, don't reason about it.**

### 3.2 My own tiling pass closed gaps Crystal leaves deliberately
The tiling pass written for 3.1 (kept, because it does correct real overlaps) stretched cells
into intentional blank spans:

```
page 2, row y=632   reference: 23.15..77.45 | (gap) | 252.15..300.75 | ...
                    mine:      23..252 (one 229pt cell)  <- gap swallowed
```

Fixed with a gap threshold: close a gap only if it is small (≤6pt horizontally), since that is
the doubling artefact tiling exists to remove; a larger gap is a cell Crystal does not draw.

### 3.3 The vertical threshold then swallowed a real band
Same guard at 6pt vertically deleted the rule at page 2 abs y=626.2, because the reference's
row ends at 626.2 and the next table starts at 632.05 — a genuine 5.85pt blank band. Crystal's
*horizontal* cell gaps run to ~4.6pt but a vertical gap that size is a real gap, so the
vertical threshold is tighter (3pt). Rule differences 1 → **0**.

### 3.4 The INPEX logo was missing from all 7 pages
`get_drawings()` and `get_text()` do not return images, so a pure trace omits the logo
entirely — **the same defect R07.002 and R07.003 both shipped with.** Reference places it
identically on every page: abs (22.65, 41.20)–(150.20, 63.20) → local `-1,13 128x22`.

Then two further errors on the asset itself:
- `output/logo.png` (already in the folder) is a **different INPEX mark** — aspect 1.903
  against the reference's 5.791 — so JasperReports' default `RetainShape` aspect-fitted it
  into a fraction of the box.
- Extracting the reference's embedded XObject gave a wordmark reading **"INbEX"**: the image is
  a stencil whose SMask carries the letter shapes, and extracting the XObject alone drops it.

Resolved by **rendering the logo region of the reference page at 600dpi** (`extract_001_logo.py`
→ `logo_ref.png`, aspect 5.783) and using `scaleImage="FillFrame"`. That reproduces exactly
what the reference displays, mask included.

## 4. Remaining items — all verified NON-defects

Each was checked against raw data rather than assumed benign.

### 4.1 "2 text differences" — a non-breaking space
Page 4, `'WB6.P - Ballast water tank 6 Port - Water ballast suction transmitters U/S'`.
The reference uses `\xa0` (non-breaking space) before `U/S`. **My JRXML also contains `\xa0`**
(verified by reading the file). The difference is introduced by PDF *text extraction* of my
output — Arial maps nbsp to the normal space glyph. Rendering is identical.

### 4.2 "1 value >4pt out" — SIMOPS
Page 6. The check compares rendered x-centres:
```
REF  'SIMOPS          '  len=16  bbox x 181.60..239.13   centre 210.4
GEN  'SIMOPS'            len= 6  bbox x 181.00..215.96   centre 198.5
```
The reference span carries **10 trailing spaces**, which widen its bbox and move its centre.
Both start at x≈181. The text has not moved; the centre metric has.

### 4.3 "17 gridline ink mismatches"
- **13 are ≤0.6pt** — rendering rounding, the same residue class the owner accepted on R07.006.
- **4 are large and are the probe landing on text, not gridlines.** At page 1 abs x=25.1 and
  805.3 the reference and mine have *identical* thin rects at identical positions; the 4.44/5.04pt
  "line width" is a glyph ('CPF' starts at x=24.65, 'Health, Safety & Environment' at 22.65).
  At x=621.8 **neither** document has any line — pure text.
- `compare_ink` reports **0 unmatched** lines: every reference gridline has a counterpart.
