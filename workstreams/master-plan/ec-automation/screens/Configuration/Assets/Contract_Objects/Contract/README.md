## DB self-clean check (ground truth — OV_CONTRACT)
Run BEFORE and AFTER the live suite, from a fresh connection each time (never reuse a mid-test
session), to confirm the fixed test code (`AUTOTEST_CONTRACT`) is absent and no `AUTOTEST%`
residual rows exist:
```sql
SELECT COUNT(*) FROM OV_CONTRACT WHERE CODE = 'AUTOTEST_CONTRACT';   -- expect 0
SELECT CODE FROM OV_CONTRACT WHERE CODE LIKE 'AUTOTEST%';            -- expect no rows
```
(`libraries/DbVerify.py` uses the generic `CODE` column on every `OV_*` view, not a
screen-specific `CONTRACT_CODE` column.) A read-only helper script used by this backfill to run
the same query from a fresh `oracledb` connection is at
`Workplaces/contract-backfill/db_selfclean_check.py` (gitignored scratch, not a permanent
deliverable — see `evidence/backfill_2026-08-27/db_selfclean_check_output.txt` for its captured
output: both counts = 0).

## Key facts
- Navigator **Business Unit** dd `nav:form:G:0:R:1:C:1:dd` is mandatory; pick `TS5 BU` + GO before
  the grid (`manageObject:form:T_data`) loads. As of PR #546, the fill goes through the shared T2
  `Apply Navigator From Properties`, driven by `testdata/contract_navigator.properties`.
- Insert **End Date** and **Contract Year Start** are BOTH mandatory on `objectForm` — unusual for
  an OV-GM Insert form (most screens leave End Date optional/delete-only). Insert **Contract
  Area** dd must equal `TS5 Contract Area` (must sit under the nav BU=TS5 BU scope) or the
  inserted row never lists in the filtered grid.
- OV-GM grids redraw lazily after Save+GO — the T3 keywords wait for the row before asserting.
- The RF suite uses the FIXED test code `AUTOTEST_CONTRACT` (not a per-run timestamp — since PR
  #546); the Playwright driver still uses the original `AUTOTEST_CT_<timestamp>` per run.
- Live runs can hit transient `Could not find active page` UI-timing flakes during AJAX-heavy
  redraws (seen 3x during the original PR #546 conversion, seen once during this backfill's
  evidence capture — 1 retry, then clean 5/5). Not a business-logic defect — DB reads after a
  flaky attempt already show the correct end state.
